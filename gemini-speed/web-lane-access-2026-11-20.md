# Gemini Web 车道接入通道分析（2026-11-20）

> 结论先行：**HY2 不是协议绑定，是当前唯一同时满足「快 + 加密 + 不暴露」的接入通道**。本文记录链路结构、替代路径取舍与去 HY2 化的正确姿势，供两台机器共同遵循。

## 一、链路结构：两段，一段硬一段软

```
本机 (9445) ──HY2 隧道──> VPS web2api (8083) ──WARP 出口──> Google
        ↑ 这段可换                    ↑ 这段是架构决定
```

**VPS 段不能挪**，原因（多轮排障换来的）：

1. **Pro cookie 池**在 VPS（lapland1009，db 管理 + 健康度跟踪）
2. **WARP 出口**：Google 风控看出口 IP 画像，机房 IP 稳定且可与 cookie 绑定；家宽 IP 直连 Gemini 风险高、漂移更凶（11-17 停机就是出口漂移教训，已有 warp-watch 看门狗）
3. 长任务 7×24 依赖 systemd 服务 + 看门狗 + 代理熔断自愈，这套设施只在 VPS 成立

## 二、本机→VPS 段的替代路径对比

| 路径 | 结论 | 理由 |
|---|---|---|
| **HY2 隧道（现状）** | ✅ 采用 | QUIC 拥塞控制暴力快（17MB 二进制秒传）；流式输出低延迟；全程加密；`start-hy2.bat` 一键 |
| 公网直连 `VPS_IP:8083` | ❌ 禁用 | 裸 HTTP：API key + 256-512K 对话内容明文裸奔；`/admin` 管理面（cookie 管理、请求明细）暴露公网；VPS 防火墙也未开口 |
| 天津跳板 SSH 转发 | ❌ 不可用 | CN-US 链路 <30KB/s——256-512K 任务每个请求体都要走这条线，仅上传即数十秒，流式体验崩坏 |

## 三、若未来要去 HY2 化（正确姿势）

不是开 8083 公网，而是：

1. VPS 上加 TLS 反代（Caddy 现成，与 gemini-gw 体系同栈）指向 `127.0.0.1:8083`
2. 仅放行带 API key 的 `/v1/*`，`/admin` 绑 localhost 或加 IP 白名单
3. `per_ip` 限流从「隧道全算 127.0.0.1 一个桶」变为按真实 IP 分桶（更健康，但注意公司机与家里是两个桶）

触发条件才做：HY2 线路质量劣化且无替代节点、或需要第三方（非自家机器）接入时。目前无理由动。

## 四、两台机器的接入纪律

- 家里：双击 `start-hy2.bat`，`check.bat v5` 深测绿再开任务，用完关
- 公司机：client.yaml 自带 web 车道（9445 转发），同样纪律
- 配置参照：`gemini-speed/opencode-web-models-2026-11-20.md`
