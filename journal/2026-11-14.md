### 4. web 车道 128KB 墙攻防战（核心难题）
- 现象：agent 会话 prompt 140-170KB 全部撞 128KB 上限，每轮转附件模式（附件另有约 160KB 可读墙），24 秒级体验
- 解药为 zexadev 内置 multi_turn（默认关）：服务端会话续接，客户端照常重发全历史，服务端识别后只发增量
- 踩坑：config.json 改不动它（DB 持久化配置优先级更高），必须走管理 API 全量 PUT
- 实测：301KB 首轮，续接轮只发 58 字节，历史留服务端，1M 窗口内全量保真
- 流式验证：思考块 4.6s 起渐进到达，正文每秒约 1.5KB 持续细流，协议层完整

### 5. 传输侧优化收口
- gzip 解压垫片：VPS 8084，Go 二十行，systemd 常驻，透传加解压双模式验证通过；实测收益小（传输从来不是大头）

## 公司机部署指南（web 车道）

1. git pull dsh-base（拿到三车道模板与 check.bat v4）
2. 公司机 hy2 目录：确认 client.yaml 含 web-lane 段（9445 转 8084，模板已是三车道版），隧道参数照旧
3. 放置三个 key 文件（与家里同目录结构）：cpa-api-key.txt、aistudio-api-key.txt、web-api-key.txt，值从家里对应文件抄，渠道自传
4. 双击 start-hy2.bat 起隧道，跑 check.bat，应见三行 OK
5. opencode 配置增加 web 渠道：package 用 aisdk 加 at-sdk 加 google，baseURL 指本机 9445 的 v1beta，apiKey 用 file 引用指向 web-api-key.txt，模型挂 gemini-3.8-flash 与 gemini-3.8-flash-thinking（模型对象带 capabilities 与 limit，照 aistudio 渠道结构抄）
6. 服务端无需任何操作：multi_turn、垫片、带宽都是 VPS 或客户端侧已完成的配置
