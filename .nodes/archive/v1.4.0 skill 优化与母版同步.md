- **踩坑记录**：
  1. **PS 5.1 解析对 BOM 极度敏感**：无 BOM 的 UTF-8 .ps1 会被按 GBK 解码，中文注释里的字节会破坏引号配对，报出"Unexpected token"等假语法错误。母版 .ps1 必须 BOM+CRLF。
  2. **PS 5.1 单引号字符串里不能出现 `<` `>`**：会被当成重定向运算符导致解析失败；写提示文案改用 `[output]` 或拆成变量。
  3. **JS `toISOString()` 是 UTC，PS `Get-Date` 是本地时间**：锁文件时间戳混用会导致超时判断错乱（刚建的锁被判为 480 分钟前）。跨语言实现锁时必须统一用本地时间格式。
  4. **Node 的 stderr 输出会被 PS 当 NativeCommandError**：跨平台脚本的 WARN/FAIL 应走 stdout，避免在 PowerShell 里被包装成错误记录。
  5. **`trim-decisions` 的标题匹配不能写死 `^## \[`**：既有 DECISIONS.md 存在 `## 日期 · 标题` 无方括号格式，写死前缀会漏条目（21 条被误判为 20）。改用 `^## ` 即可（文件名用单个 `#`）。
  6. **verify -Completed 的 -Node 不能含 `/`**：脚本会因非法文件名字符抛错；既有惯例是 PROGRESS 行写完整描述、归档文件名用无斜杠短名，且短名须是 PROGRESS 行的子串。
- **遗留**：无未决缺陷。跨平台 save.mjs 已具备功能对等，但 `derive-next-batch.ps1`（DSH 专用派发）与 `compact-context.ps1`（L2 桥接）仍为 PS 独占，非 Windows 环境暂缺这两项能力。
