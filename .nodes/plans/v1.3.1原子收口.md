## 批1 执行材料（v131-b1 从本节开始）

**设计点（已敲定，勿再发散）**：CONTEXT 内容经**临时文件**传入。

**commit 契约**：

```
save.ps1 commit -Session <S> -Node <节点名> -Batch <M> -ContextFile <path>
```

执行序列（单次脚本调用内完成）：①ContextFile 存在性校验（缺失 throw，不动锁）→ ②取锁（复用现有 lock 逻辑：自有刷新/超时覆盖/未超时 FAIL）→ ③Read-Utf8(ContextFile) → Write-Utf8(CONTEXT.md) → ④删除 ContextFile → ⑤unlock → ⑥`verify-batch -Node -Session -Batch` 并透传其退出码。

**三场景语义**：
- 正常：全链成功 exit 0，ContextFile 已删
- 锁竞争 FAIL（②步）：exit 1，**ContextFile 必须保留**（重试无需重写内容）
- verify-batch FAIL（⑥步）：exit 1，CONTEXT 已落盘（内容无损），提示信息指明校验失败项

**输入材料（只读三份 + 本节，约 12K）**：
1. `node-architect\skill\scripts\save.ps1`（~310 行——现有 lock/unlock/verify-batch 逻辑全部复用，只加分支）
2. `.nodes\plans\v1.3.1原子收口.md` 本文件
3. `.nodes\PROGRESS.md` 节点 6 行（验收标准）

**边界（禁做）**：不动 verify/lock/unlock 既有分支行为；不动 SKILL.md frontmatter（批3）；不碰 .agents 镜像与 install/pack（批3）；不改 plans/README.md（批3 回灌）；UTF-8 降噪与 verify-batch 盲区是批2 范围，本批禁做。

**编码铁律**：母版 .ps1 必须 BOM+CRLF（v1.3.0 踩坑：LF 行尾 + GBK 解码破坏解析）；自测脚本输出若乱码属控制台编码，非脚本缺陷，勿因此改脚本逻辑。

**验收自检**：①三场景各跑一遍并记录退码；②正常场景后 CONTEXT.md 与 ContextFile 原内容一致且 ContextFile 已删；③锁竞争场景后 ContextFile 仍在；④批末按纪律用 `commit` 完成自己的收口（吃自己的狗粮），verify-batch(v131-b1/批1) 全 [OK]。
