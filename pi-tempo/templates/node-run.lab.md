# /node-run — 执行节点

目标节点与补充要求：$ARGUMENTS

**本命令即授权**：打出 `/node-run` 就等于说了「开工」。读档后不要停下等确认，直接连续执行到节点收口或触发下方「停止条件」之一。本模板对「确认」的口径**优先于** node-architect 铁律 1 与项目 `AGENTS.md` 的「复述后确认再动手」——那条规矩针对「读取节点xx」这类只读交接；本命令是执行指令。

## 第 0 步（两件事，顺序不可换）

**0.1 路径纪律**：所有脚本路径照抄本模板与 `AGENTS.md`，禁止用 Glob/Grep 搜索定位（`.agents`/`.pi`/`.nodes` 点目录对搜索工具不可见，搜了必空转）。

**0.2 加载 skill（同一批发出）**：在**同一批**工具调用里发出两个 `Skill` 调用（串行两次白等一轮）：

1. `node-architect` —— 节点协议（读档 / 节点登记 / 存档流程 / save.ps1 动作与退出码语义）
2. `pi-tempo` —— 执行节奏纪律（往返预算 / 批量编辑不重读 / 多任务切分与并行派发 / 子代理依赖调度 / 工具契约与退出码判成败）


## 执行流程

1. **读档（一批并发）**：把 `.nodes/CONTEXT.md`、`.nodes/PROGRESS.md`、该节点 `.nodes/archive/<节点名>.md`（或 `.nodes/plans/<短名>.md`）、`.nodes/DECISIONS.md` 最近条目**放在同一批工具调用里一次发出**——分次读纯属浪费往返。
2. **一行状态**：读档后先用一两句话交代「当前节点 / 验收标准 / 下一步」，**交代完立即进入第 3 步**——不要在这里结束回合，也不要问「是否开工」。
2.5 **接力分支（档案有接力表时，本会话＝调度器）**：读档后若节点行带 `委派:执行接力`（或 plans/返工清单有接力表）——**本会话禁止 Read/Edit/Write 任何源码，也禁止自己跑测试/门禁命令**（验证归执行棒与复审棒；272-R1 实测：主会话越权写码＋自跑门禁＝两轮 3 连败失败循环＋~15 分钟重复劳动）。派发后主会话合法动作**仅四类**：①读子代理报告并记 facts ②备下一棒简报 ③存档/SESSIONS 留痕 ④`git status --porcelain` 越界检查。**「派完不空等」在接力模式下＝做这四类，不是自己去写码——本条优先于 pi-tempo §10 的空等建议。**照单循环：读棒简报（接力表行＋facts）→ `Task(gemini-fixer)`（六段简报：GOAL/验收/文件集+禁区/已验证事实/验证/终止）→ `TaskWait` 收敛 → 事实追加 `.nodes/relay/<名>/facts.md`（各段 ≤300 字）→ 越界检查 → 下一棒；全棒完成 → 复审棒（independent-review，异构；**报告须含逐项行号证据，不完整即重派**）→ 存档收口。失败处理：fixer 失败 → 修简报重派；**同棒重派 ≥2 次即熔断**停棒报告用户（失败三分类：瞬时/环境/方法死路）。无该标记 → 按第 3 步正常执行。
2.6 **并行批与双节点（v1.0.8）**：接力表「批」列同号＝同批，一次消息并发派发（≤3 支，TaskWait 等全收）；并行批按运行时域切（pytest ∥ vitest ∥ docs），同域内被其他棒 import 的文件＝共享接缝、不可并行；i18n 键/路由注册/门禁白名单/barrel 等共享面归**串行收尾棒**。接力开工先 `git status --porcelain > .nodes/relay/<名>/baseline.txt`，越界检查只看「快照后新增且不在本棒授权集」的行；任何棒在跑期间门禁只跑路径域（gate.ps1 -TsFiles/-Vitest 指定文件），全仓回归由回验棒在全部棒落地后跑一次；越界改动＝revert 不 merge。同仓最多 2 个接缝不相交的节点并行执行（>2 或接缝相交→串行；跨仓随意）。
3. **执行**：按该节点行的验收标准推进。开工先做侦察（测试基建盘点 / 依赖与命令确认），结论用 `save checkpoint -Recon` 登记；同时在 SESSIONS 里声明**委派映射**（见「并行派发」节）。**多要求先切分再动手**——先做下方「切分」节的判定表，把可并行的要求写进 TodoWrite 批次，再按批执行。**逐项推进到底**，不要每完成一项就回来问一次。
4. **工具纪律**（每条都是本机实测踩出来的）：
   - 改文件走 Edit 行操作：带正文的 PUT 必须写冒号（`PUT 12.=12:` 后跟 `+` 行）；`CUT` 不带正文；**写入成功后文件 tag 会变**——若还要再改同一文件，得先重新 Read 拿新 tag，**所以尽量把同一文件的改动一次性批量写完**；大范围改写直接 Write 整文件重写。
   - Bash：预计超过 60 秒的命令显式传 `timeout`（秒），或拆成小步。
   - **判成败只看 `exitCode`**：`npm warn` / `DeprecationWarning` 会写 stderr 但退出码为 0，不是失败，不要因此重跑或改代码。
   - 临时脚本先 `node --check` 再运行；**先跑最小子集**（单个测试文件），全部改完再跑全量，不反复全量重跑。
   - **往返预算**：同一文件**一次读够**，别分窗口反复读；**同一文件的多处改动合并成一次 Edit 调用的多个 op**（用原始行号、自底向上、op 之间不重叠），别「改一处→重读→再改一处」；读之前先问「已有的信息够不够下笔」，不要拿重读当保险；互相独立的 Read/Grep/Bash **同批发出**；「I will …」**每批一行**；机械性只读活派给 `gemini-scout`（钉 low 档）。
   - **锚定输出（v1.0.2，跳过＝该批作废）**：每个批次开工时，在**助手正文**（不是 thinking）先写一行 `ANCHOR: 本批最大风险 → 要验证的点 → 适用规则 §号`，然后才发工具调用。机制：上下文超过 ~20 万 token 后，开工时装载的 skill 规则注意力会衰减到 ~2%（实测 271：规则在上下文里但没被执行）；被动重读无效，**自己生成的 token 才能把注意力拉回**。收口时 grep 会话 `ANCHOR:` 次数应 ≥ 批次数。
   - **上下文守门（Flash 长上下文是硬伤）**：预判要读 **>30 个文件或 >3000 行**才能动手 → 先派 `gemini-scout` 测绘，主线程只收结论；大工具输出（测试日志 / 大 diff / grep 海量命中）先派廉价子代理摘要再进主上下文。实测主线程自己读 32 个文件，上下文从 1.1 万涨到 14.9 万 token——之后每一趟都背着它。
   - **子代理门禁**：`gemini-3.8-flash`（CPA）与 `deepseek-v4.1-flash` 均已开启「Available for AI delegation」，可直接派；日后若换模型，未开该开关的会被 `PERMISSION_DENIED`（设置 → 模型里打开）。
5. **门禁**：**每批改动落地就跑该批的最小子集**；收口前跑全量 `node scripts/check.mjs`，**exit 0 才继续**——别攒到最后才发现错了返工。
6. **收口**：
   - 验收达成 → 写 `.nodes/archive/<节点名>.md` → 写 CONTEXT 暂存文件 → 跑
     `powershell -NoProfile -ExecutionPolicy Bypass -File .agents\skills\node-architect\scripts\save.ps1 save -Node <节点名> -Session <会话> -ContextFile <暂存> -Completed -Project <项目根>`
     （`-Completed` 会校验归档文件存在）→ 向用户报告 verify 各项结果。
   - 未达成 → `save.ps1 checkpoint -Node <节点名> -Session <会话> -Note "<断点>" -Project <项目根>`，报告剩余项与下一步。
   - **跨目录调用必须显式传 `-Project`**（该参数默认取当前目录，跨项目会写错文件）。

**开工前先量规模（拆节点阈值）**：读档 + 侦察后，若预判满足**任意一条**——**预计实现 >2000 行** / **>100 处改动** / **>40 分钟**——**不要一口气做完**，按「切分」表的批次拆成 2–3 个子批次，逐批走「实现 → 局部验证 → 暂存」，批间用 `save checkpoint` 留断点。

**过大的节点开工时就拆，别等跑不动了才拆**——规则只能削掉浪费（约 15–20%），削不掉工作量本身。

## 切分（多个修改要求的并行判定）

**通用判定协议见 skill `pi-tempo` §9**（枚举文件集 → 重叠判定 → 接口依赖 → 共享文件单 owner → 越界检查 → 规模过大就拆批）。本仓要点：

1. **枚举文件集**：路径级，来自证据（验收标准点名、Grep 命中、已读文件）；**已读到=确定，靠命名猜=推测**。推测文件先去 Grep 确认，确认不了就串行。
2. **有没有另一个任务也动同一个文件？** 有 → **串行**。
3. **有没有接口依赖？**（任务 A 定义的类型/函数被 B 使用）→ 二选一：**契约冻结后可并行**（主线程先写签名/骨架并跑通验证，再让两支并行实现）；否则**串行**。

### 硬规则

- **同一个文件 = 串行**，哪怕只是不同函数、不同区段。Edit 是行操作且写入后 tag 会变，两个 agent 同改一个文件必然互相 `EDIT_TAG_MISMATCH`。
- **共享文件只给一个 owner**：**注册/入口类**（本仓：`src/i18n/index.js`、`src/index.js` barrel）、**孪生文件**（`src/i18n/messages.zh.js` ↔ `messages.en.js`，同键必须一起改）、**共享测试基建**（`test/messages.test.js` 校验 zh/en 键一致）——并行任务不碰它们，**主线程在并行落地后统一收尾**。
- **每轮并行落地后做越界检查**：`git status --porcelain` 只应出现各任务授权集内的文件；越界 = 划分失败，先处理再继续。
- **门禁**：每批落地就跑该批的**最小子集**（相关测试文件）；全量 `node scripts/check.mjs` 由主线程在所有并行批落地后跑一次。

### 切分表（产出格式，写进 TodoWrite）

| 任务 | 文件集（确定 / 推测） | 关系 | 批次 |
|---|---|---|---|
| T1 A 组 / T2 B 组 | `a1.js`、`a2.js` / `b1.js`（确定） | 两两无交集 | 批1 |
| T3 文案与注册 | `src/i18n/*`（确定，共享） | 共享文件，**主线程收尾** | 批2 |

批次规则：**批内两两文件集不相交**；跨批串行；一批 2–3 个。

**TodoWrite 只登记「批次」粒度，不要登记单个任务**——按任务逐条列（T1/T2/T3…），模型就会一个个做完再回来；
按批次列（`批1: T1+T2（a.js、b.js，文件集不相交）`）才会合批执行。实测两种写法差了整整一批往返。

### 切法建议

按**模块/功能域**分组切最省事；其次「实现与测试分离」（`x.js` 与 `x.test.js` 天然不相交）。**切不出可并行的组合就老实串行**——硬凑只会返工。

## 并行派发（子代理）

并行只在**任务相互独立**时省时间（用时 ≈ 最慢那支）；每个子代理要付首字延迟，**一轮 2–3 个为宜**。

**派发的前提是上方「切分」表**——先切分再派发，宁可全串行也不要让两个 agent 碰同一个文件。

三个全局自建子代理（`~/.agents/subagents/`，已钉模型与档位）：

| 子代理 | 用途 | 模型/档位 | 工具 |
|---|---|---|---|
| `gemini-scout` | 大范围只读测绘（结构、调用点、测试分布） | gemini-3.8-flash · **low** | Read/Glob/Grep/Bash（**无写权限**） |
| `gemini-fixer` | 无共享文件的双线实现 | gemini-3.8-flash · **high** | Read/Glob/Grep/Edit/Write/Bash |
| `independent-review` | 收口独立复审（异构家族，盲点不同） | **deepseek-v4.1-flash** · high | Read/Glob/Grep（**无 shell、无写权限**） |

### 什么时候派 fixer（触发条件，别看感觉）

派 `gemini-fixer` **只在同时满足三条**时划算：① 独立文件集；② 主线程手上有别的活；③ **规模够大**——该支预计实现 **>2000 行**、或自身 **≥8 个串行往返**（改完要跑测试、看结果、再修的迭代，不是一批能写完的）。

**耦合判据（拆前必查）**：该支的文件要读 **≥3 个属于其他分支的文件**才能确定接口 → **不拆**——耦合成本大于自身工作量时，并行必亏。

实测：21 文件的节点，主线程 1 个往返并发写 16 个文件（99.6s）落地；派 3 个 fixer 要 ≈10 个往返。**文件多 ≠ 该并行**。

### 「机械步降档」

代理无法自切思考档（档位是会话级设置），可行的只有：机械只读活派给钉了 `low` 的 `gemini-scout`；或你手动在检索／跑测试阶段切 `low`。**别让机械活占住主线程的 high 档往返。**

### 依赖怎么排（子代理之间没有通信通道，只有主线程能调度）

- **无依赖** → 同批并行。
- **接口依赖** → 主线程**先冻结契约**（签名＋骨架并跑通验证）→ 再同批并行。
- **数据依赖**（B 必须先知道 A 的结论，例：要改哪些文件）→ **两批**：A 批（只读、低档）→ 主线程汇总并重切分 → B 批。别让 B 先跑再指望 A 的产出「大概如此」。
- **汇聚**（多支产出要合并）→ 同批并行 → 主线程 fan-in（合并＋越界检查＋单次门禁）。
- **派完不空等**：主线程同时干不依赖它们的事；收敛用 `TaskWait`，`mode:"any"` + `minCompleted` 够用就走。
- **任务小且必须串行 → 主线程自己做**（省掉"写简报＋读报告"两次往返）。

### 收口独立复审（开工时声明映射，写进 SESSIONS 的「委派状态」行）

```
本端映射=收口独立复审→independent-review（deepseek-v4.1-flash·high·只读）
```

- 优先用 `independent-review`：它与实现者**不同模型家族**，盲点不一样；内置 `code-reviewer` 继承父会话模型（Gemini 审 Gemini，同源盲点）。
- **复审简报必须给足**：验收标准 + `git diff --name-only` 清单 + 关键 diff 摘要。复审者无 shell，自己重新探索一遍既慢又易偏。
 - **复审跑的时候主线程不要空等**——先把收口能做的做完：① 写 `.nodes/archive/<节点名>.md` 正文；② 生成 CONTEXT 暂存；③ 把 `save.ps1` **一次读完**（960 行一次读，别分 4 段试探）；④ 预读门禁脚本与 PROGRESS。这些与代码文件不相交，不会跟复审者抢文件。**判据：从 `Task` 返回到 `TaskWait` 之间至少塞 2 个往返的活**；只做 1 件就等 = 白烧掉整段等待（实测一次空转 107 秒 ≈ 全程 20%）。

## 停止条件（只有这几种才停）

1. 需要用户决策（方案二选一、改需求、提供凭据等模型无法自决的事）。
2. 破坏性 / 不可逆操作需要批准。
3. 节点验收标准已达成 → 执行第 6 步收口并存档。
4. 真实阻塞（环境不可用、依赖缺失且装不上、锚点失配需人工）。
5. 上下文即将压缩且本会话无法继续 → 按节点协议留断点。

除以上之外**不要停下等确认**：本回合的交付物是该节点的实际进展（改动 + 验证 + 存档），不是读档摘要。

## 纪律

- 节点号只能由 `save.ps1 next-node` 分配；`PROGRESS.md` 只改自己节点的行；`DECISIONS.md` 只追加。
- 断点场景（会话中断 / 异常终止）**不原样重发同一句**：进度在档案不在对话，照常读档恢复。
- 本模板只负责「执行一个已存在的节点」；新计划请走 `/plan-node`，日常交接用「读取节点xx」。
